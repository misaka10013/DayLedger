# 00 · 这是什么

> **30 秒版**：一个只给自己用的安卓时间记录 App，把一天切成分钟记账，源码全在这里。
> 不讲情怀，只讲它解决什么问题、适不适合你。

---

## 30 秒读懂

你一天干了什么？大部分人答不上来。不是因为忘，是因为**没有工具按「分钟」记账**。

这个 App 的做法极简：你在做什么的时候，点一下。它就记下「从几点几分到几点几分，你在干什么」。
一天必须凑满 **1440 分钟**，你没记的那部分会显示成一条 `▨ 未记录` —— 它不会猜、不会补、不会悄悄并给邻近的事项。

就这些。剩下的全是为了让这件事**不别扭**：改时间不留暗坑、模板能自动填、统计能看出你这周到底把时间花哪了。

## 它适合谁

| 你的情况 | 适不适合 | 说明 |
|---|---|---|
| 想找一个能自己掌控数据的时间记录 App | ✅ | 纯本地、无账号、无联网（除了你自己开的云同步） |
| 想学安卓开发，找一个**有真实业务复杂度**的练手项目 | ✅ | 数据层有不变式、UI 有几何计算、还有 500+ 条测试 |
| 想给自己的小工具做「一天 1440 分钟」这类记账逻辑 | ✅ | `domain/` 那层是纯 Kotlin，可以整个搬走 |
| 想找个现成 App 直接用 | ⚠️ | 能用，但它没有提醒、没有多端同步、界面也不花哨 |
| 想做 iOS / 想要跨端 | ❌ | 只有安卓。界面层不能直接复用 |
| 想做多人协作 / 团队工时统计 | ❌ | 单人单设备设计，云同步只是「备份 + 给 AI 读」 |

## 一分钟看明白它在干什么

```
时间线（今天）

00:00 ┃████████  睡觉            7时15分
07:15 ┃████      洗脸洗漱         18分
07:33 ┃████      吃饭            22分
07:55 ┃██████    开车通勤         35分
08:30 ┃████████  打工           5时30分   ← 一段可以很长
14:00 ┃▓▓▓▓      做饭            45分     ← ▨ 未记录 会长这样
14:45 ┃████      玩手机          30分
       └──────────────────────
       底部：[ 结束 ]  现在在记：打工 · 已持续 1时12分
```

- 点底部「结束」→ 弹出事项网格 → 选一个 → 上一件事在此刻结束，新的从此刻开始。
- 记错了？点那一段，直接改起止时间。改出来的空隙**会变成一条 `未记录`**，不会凭空消失。
- 忘了记？点那条「未记录」补上。
- 每天都是这一套，一秒钟能点完。

## 上手版：三个词就够

想看懂代码，只需要先懂这三个词：

**① 段（Segment）**
数据库里的一行，表示「某天 从 A 分钟 到 B 分钟 在做什么」。
注意单位是**分钟**，不是时间戳。`a=480, b=570` 意思是 08:00 到 09:30。

**② 密铺（Dense）**
每一天的所有段首尾相接、加起来正好 1440，中间不许有空、不许重叠。
你看到的「未记录」不是「没有数据」，而是一条 `source=GAP` 的正经记录 —— 它有 id、能被点击、会被统计。

**③ 唯一入口**
所有「跟着某个东西走」的显示，都必须有**一个**地方负责同步。
这个项目在这一条上栽过八次（周条不跟翻页、热区不跟柱子、小部件各抄一份刷新链…），详见 [08 踩过的坑](08-我们踩过的坑.md)。

## 深挖版：为什么值得开源

三个理由，都很实在：

**1. 它的复杂度是「真长出来的」，不是设计出来的**
市面上讲架构的文章一堆，但真实项目的复杂度来自**边界情况**：改时间撞到邻居怎么办、删掉的记录不能自己长回来、
跨天的那一分钟到底算哪天、小部件和主界面怎么不打架。这些这里都给出了有测试兜底的答案。

**2. 它的测试是真在测东西**
524 条断言，不是「覆盖率好看」那种。每一条都对应一次真机事故 ——
比如有一条专门盯「桌面小部件刷新有七成是假刷新（`updateAll()` 2ms 返回但根本没重绘）」。
详见 [08 踩过的坑](08-我们踩过的坑.md)。

**3. 它承认自己不是标准答案**
代码里到处是「这么写是因为当时踩了这个坑」的注释，包括**试过又撤回**的方案。
看一个项目为什么**不**那么做，往往比看它怎么做更有用。
