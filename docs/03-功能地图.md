## 上手版：按页面走一遍

底部导航只有三格：**时间线 / 统计 / 设置**。别的都收进设置里，因为低频。

### ① 时间线（主页面）

```
┌──────────────────────────────┐
│ 10月25日 周日  ▾        ⋮    │  ← 点日期出月历；⋮ 是整天复制/粘贴
│ 已记录 12时49分 · 未记录 2时37分│
├──────────────────────────────┤
│ 模板运行中 · 工作日     点此退出│  ← 只有模板开着才出现
├──────────────────────────────┤
│ ████ 打工        1分          │
│      15:25 → 现在 · 模板       │
│ ▨ 未记录        2时37分        │  ← 点它可以补记
│      12:48 → 15:25           │
│ ████ 吃饭        25分          │
│      12:23 → 12:48           │
│              ⋮ 往前翻          │
├──────────────────────────────┤
│ [ 结束 ]  现在在记：打工 1时12分│  ← 最常用的按钮，位置永不自动变
└──────────────────────────────┘
```

| 你做什么 | 会发生什么 | 代码在哪 |
|---|---|---|
| 点底部「结束」 | 弹出事项网格，选完上一件在此刻结束 | `TimelineRepository.pick()` |
| 点某一段 | 弹操作菜单：改时间 / 改内容 / 删除 | `RecordActionSheet` |
| 点「未记录」 | 补记 —— 选一个事项填进去 | 同一个 `pick()`，多传一个时间段 |
| 点日期 | 弹出月历，可跳到任意一天 | `MonthCalendar` + `CalendarGrid` |
| 点 `⋮` | 整天复制 / 粘贴（粘贴会覆盖，弹确认 + 4 秒撤销） | `DayClip` |
| 点顶部「模板运行中」 | 退出模板 | `TemplateRepository.stopTemplate()` |

### ② 统计

四个视图，都用同一份 `StatsCalc`：

| 视图 | 回答什么问题 |
|---|---|
| 周 | 这周每天都干了什么（可点某天看明细） |
| 月 | 这个月各项占比、趋势 |
| 单日对比 | 一天 24 小时里几件事各自的时间分布（叠加曲线） |
| 分类占比 | 一级分类各占多少（就是这个 App 的「钱花哪了」） |

⚠️ **占比的分母不是恒 1440**，是「到此刻为止」；历史日是 1440。
还没到的时间不算「未记录」—— 否则你早上看统计会觉得自己 60% 时间在浪费。

### ③ 设置

| 分组 | 里面有什么 |
|---|---|
| 数据 | 分类、事项、标签、模板、导入旧数据、云同步 |
| 关于 | 版本号 |

设计原则：**只有「用户真的可能改它、且改了会改变行为」的东西才有资格进来**。
所以没有「无间隙计时」「一天的起始时间」这类开关 —— 那些是产品铁律，不给关，
放进来只会让人以为能关然后又关不掉。

## 深挖版：几个容易找错地方的功能

### 模板到底在哪跑？

三个文件，别混：

| 文件 | 管什么 |
|---|---|
| `domain/TemplateEngine.kt` | **纯函数**：给定「模板 + 当前时刻」，算出该铺哪些段。没有数据库、没有 Android 依赖。 |
| `data/repo/TemplateRepository.kt` | 模板的增删改、启用/停止、跨天处理 |
| `TimelineRepository.applyTemplate()` | 真正把算出来的段写进数据库 |

**为什么引擎要是纯函数**：因为「该铺哪些段」这件事最容易写错（周末、跨天、运行中改模板……），
纯函数才能用几十条单元测试把它钉死，不需要建库、不需要模拟器。

### 刷新链：每次打开 App 会跑四个步骤

```kotlin
syncTemplateDay()   // ① 跨天了没？该不该换到今天
carryOver()         // ② 昨天没结束的记录，接到今天
ensureDense(day)    // ③ 把 [0, 此刻] 补齐（用「未记录」填）
applyTemplate(day)  // ④ 模板把空白填上
```

⚠️ **顺序是死的，不能换**：

- `ensureDense` 和 `applyTemplate` 反了 → 两个互相打架，模板刚填的又被判成空白
- `carryOver` 挪到 `ensureDense` 后面 → **再也不接续，而且不报错**
  （`ensureDense` 的自愈逻辑会把「非今天的进行中记录」就地封口）
  症状是「跨天接续时灵时不灵」

这个顺序在 `TimelineRepository.maintain()` 里只有一份实现，
主界面、桌面小部件、悬浮窗全走它 —— 见 [08 踩过的坑](08-我们踩过的坑.md) 的「唯一入口」一节。

### 「图形不能说谎」落在哪几个文件

| 文件 | 管什么 | 对应的测试 |
|---|---|---|
| `domain/SegGeometry.kt` | 段在屏幕上该多高、什么时候显示时间、什么时候显示名字 | `SegGeometryTest`（13 条纯坐标断言） |
| `domain/MinuteHit.kt` | 屏幕上的 y 坐标反查是第几分钟（点击判定） | `MinuteHitTest` |
| `domain/ChartGeom.kt` | 统计图柱子/曲线的坐标换算 | `ChartGeomTest` |

这三个文件都**不依赖 Android**，所以测试能跑在 JVM 上，一秒钟出结果。

见过的最隐蔽的问题：为了让细段好点，把段的显示高度抬到 22dp。
结果 22 分钟和 23 分钟两段（真实高度各 11dp）**重叠了 11dp**，
名字糊成一团 —— 而且不报错、不崩、截图上看不出来。

现在的规矩：**段按真实高度画**（只兜一个 2dp 的「至少有像素」下限），
点击判定**按分钟反查**，而不是靠把色块加粗去换命中率。
