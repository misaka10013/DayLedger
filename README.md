## 这是什么

一个**给自己用的时间记录 App**：你随时点一下「现在在干什么」，它就记下这一段的起止时间。

之前我就用了几年其他同类项目了。但有3个点让我最后选择自建。
1是我需要把我的时间记录数据实时同步给我的AI，特别是我的每日日记AI，可以结合我的时间使用数据，和我每日的事务数据对应起来。
2是我需要个自动模板，以适应我平时规律的工作日生活，降低我的记录操作成本。之前我使用的其他时间记录软件，我没遇到一个有类似合适功能的app。
3是我之前用的app有网络备份功能，虽然可以关闭，但有时候让我有点担忧是否自己的这样隐私数据被上传。大厂我当然信得过，但这种小众app，如果存在网络服务，还是会让人担心个人隐私数据的安全性。
所以干脆找上ai，我做功能需求设计和测试，ai来写软件。现在把源码整理出来，一方面便于参考学习，另一方面也便于有其他类似功能需求的人可以借鉴。

> ⚠️ **只有安卓端**。
> 如果你想跨端，这套代码的价值主要在**数据模型、业务规则和测试思路**，界面层要重写。

## 30 秒跑起来

**准备**：装 Android Studio（自带 JDK 与 SDK），把手机用数据线连上并开启 USB 调试。

```bash
git clone <本仓库地址>
cd timelog-android
./gradlew :app:installDebug      # Windows 用 gradlew.bat
```

或者直接用 Android Studio 打开，等 Gradle 同步完，点绿色的 ▶。

第一次启动会自动导入 `app/src/main/assets/legacy_timelog.json`（60 天的**合成演示数据**），
所以一进去就有内容看，不是空壳。想清空就从「设置 → 导入旧数据 → 撤销」回退。

> 💡 演示数据是 `tools/gen_demo_data.py` 生成的，跑一遍就能重新造一份 —— 改作息、改事项名都在那个脚本里。

### 想自己打发布包

```bash
./gradlew :app:assembleRelease      # 产物在 app/build/outputs/apk/release/
```

仓库里**不含签名私钥**（`key.properties` 和 `keystore/` 都在 `.gitignore` 里）。
没有它们时，构建脚本会自动退回 **debug 签名** —— 包能装能跑，只是不能拿去发版
（签名一变，老用户就升级不上了）。

想用自己的签名发版，在工程根目录建一个 `key.properties`：

```properties
storeFile=keystore/your-release.jks    # 相对工程根目录
storePassword=你的密码
keyAlias=你的别名
keyPassword=你的密码
```

⚠️ 这个文件丢了，以后就**永远发不了同名包的升级版** —— 备份到密码管理器里，别只留在这台电脑上。

## 项目结构

```
app/src/main/java/com/misaka/timelog/
├── data/           数据层
│   ├── entity/     7 张表的实体（记录、事项、分类、标签、模板…）
│   ├── dao/        SQL 查询
│   ├── repo/       ★ 业务规则的落点（时间线仓库 2600 行，是全项目的心脏）
│   ├── import/     旧版数据导入（名字 → id）
│   └── export/     数据导出（id → 名字，跟 import 是一对镜像）
├── domain/         纯逻辑，不依赖 Android（有大量单元测试就靠这层能跑在 JVM 上）
├── ui/             Compose 界面（screen / sheet / component / stats）
├── cloud/          可选的云同步（自己部署后端才用得上）
└── widget/         桌面小部件（Glance）

app/src/test/       538 条单元测试，31 个测试类
tools/              演示数据生成器等辅助脚本
docs/               ★ 分册文档，从「完全不懂编程」到「能改功能」都有
```

**想从哪开始读**：先看 `docs/04-代码结构导览.md`，它给了一条阅读路径；
最短的一条是 `domain/` → `data/repo/TimelineRepository.kt` → `ui/screen/TimelineScreen.kt`。

## 技术栈

| 用途 | 选了什么 | 为什么 |
|---|---|---|
| 语言 / UI | Kotlin + Jetpack Compose | 单 Activity，页面即函数，改界面不用动 XML |
| 数据库 | Room（SQLite） | 编译期校验 SQL，迁移有测试盯着 |
| 桌面小部件 | Glance **1.1.1** | ⚠️ 1.2.0 依赖 Compose 1.8，与本项目的 BOM 冲突 |
| 图表 | 自绘 Canvas | 只有几张图，引图表库反而更重 |
| 网络 | `HttpURLConnection` | 全项目只有一个接口，不值得为它引 OkHttp |

**权限只有一条：`INTERNET`**（而且只在你打开云同步时才用得上）。没有定位、没有通知、没有存储权限。

## 导出与备份（不联云也能把数据带走）

入口：**设置 → 导出数据**。给两种文件，各自解决一件事：

| 产物 | 内容 | 用来干什么 |
|---|---|---|
| **完整备份 `.json`** | 和内置导入文件同一套结构，包含全部记录、备注、标签、跨天链 | 换手机 / 重装 / 换签名版本后**导回来** |
| **给 AI 的 `.md`** | 先一张按分类和按事项的汇总表，再逐天明细 | 直接拖给 AI，让它分析你的时间去哪了 |

两个动作，都不需要任何权限：

- **保存** —— 系统文件选择器，你自己挑位置（下载 / 文档 / 网盘），App 只拿到那一个文件的临时写权限
- **分享** —— 系统分享面板，直接发给微信 / QQ / 任意 AI App（文件走 `FileProvider`，不碰外部存储）

### 「给 AI 的 `.md`」长什么样

```markdown
# 一天账本 · 时间记录

## 概况
- 覆盖区间：2026-08-16 ~ 2026-10-14（共 60 天）
- 已记录：1011 段 / 1440 小时

## 按分类汇总
| 分类 | 总时长 | 占已记录 |
...

## 逐天明细
格式：`起-止 事项 分钟数`；`▨` 开头的是未记录

### 2026-10-14 周三
00:00-08:12 睡觉 492m
08:12-08:40 洗漱或洗澡 28m
▨ 12:48-14:30 未记录 102m
```

最后那行是关键：**「未记录」会被显式写出来**。对 AI 来说「这段时间没记」是一条信息，
漏掉它，AI 会把前后两段当成连续的一整块，得出完全相反的结论。

> 💡 为什么不直接导 JSON 给 AI：JSON 的引号、括号、重复键名会让 token 消耗翻三倍左右，
> 而「这一天 1440 分钟是怎么铺的」在 JSON 里还得靠 AI 自己还原。Markdown 那份把摘要放最前面，
> 它回答「我时间都花哪了」根本不用往下翻。

### 闭环是测过的

导出的 JSON **能被自己的导入功能读回去**。这不是「看起来能行」——
`DataExportTest` 里有一条端到端断言：导入内置数据 → 导出 → 用导出的文件再导入 →
天数、段数、总分钟数必须完全一致。

另外两个只有踩过才知道的点，也写在代码里了：

- **备份里不写空白段**。写进去的话，导入时 `itemIdByName["未记录"]` 查不到，
  会被当成「找不到的事项」而整包拒绝。空白本来就由仓库自己补，不写反而更准。
- **今天的记录要隔一天才导得回来**。本 App 只写「已经过去的时间」，导入时会跳过今天和以后 ——
  免得和此刻正在跑的那一段打架。要换手机的话，隔一天再导最稳。

## 云同步（可选，需要自建后端）

App 可以把你改过的天增量上传到你自己的后端，让别的 AI 能读到你的记录做分析。
**这不是开箱即用的**：仓库里不含后端代码，地址和 token 都要你自己填（设置页「服务器地址」+「同步 token」）。

默认是**关**的。

具体接口约定见 `docs/06-数据怎么存的.md` 的「云端」一节。

## 测试

```bash
./gradlew :app:testDebugUnitTest
```

538 条断言，全部跑在 JVM 上（Robolectric），不需要真机、不需要模拟器，约 1 分钟出结果。

它不是「覆盖率好看」那种测试，而是每一批都对应一次真机事故：

- `DensityTest` —— 一天恒 1440 分钟（地基不变式）
- `SegGeometryTest` —— 图形不能说谎（纯坐标断言，不看数据）
- `TemplateNoTemplateLockTest` —— 那个会让模板「一下午不生效」的隐藏坑
- `MinuteHitTest` —— 点到的必须是看到的那一段
- `DataExportTest` —— 导出的备份能不能被自己读回去

## 已知边界

- **只有安卓**，没有 iOS、没有 Web。
- **单人单设备**。云同步是「备份 + 给 AI 读」，不是多端实时同步。
- **没有提醒、没有后台常驻**。这是刻意的：核心数据不依赖任何后台存活。
- **模板不是闹钟**。它只在你打开 App 时按模板，补算已经过去的时间，不会实时弹出「该睡觉了」。
