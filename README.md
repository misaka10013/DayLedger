## 这是什么

一个**给自己用的时间记录 App**：你随时点一下「现在在干什么」，它就记下这一段的起止时间。
一天必须正好 1440 分钟，少掉的那部分会显式变成一条 `▨ 未记录` —— 不猜、不补、不吞。

因为我找了一圈都没有「按分钟记账」的同类开源项目，所以干脆自己写了一个，然后把源码整理出来。
如果你也想做一个**完全掌控自己数据**的小工具，这里的结构、踩过的坑、写测试的方法都能直接拿走。

> ⚠️ **只有安卓端**。没有 iOS 版，也没打算做 —— 作者只用安卓。
> 如果你想跨端，这套代码的价值主要在**数据模型、业务规则和测试思路**，界面层要重写。

## 它跟别的时间记录 App 有什么不一样

做这个东西的过程中有三条原则被反复验证是对的，值得先看一眼：

### 1. 缝隙必须可见

改时间必然留下空隙。绝大多数 App 会**悄悄把空隙并给邻居**，于是你以为自己记满了，实际账是错的。
这里的做法是：空隙变成一条**有 id 的真实记录**（`source = GAP`），它参与统计、能点击、是补记的唯一入口。

**一天恒等于 1440 分钟**，这不是口号，是数据库层面的不变式 —— 每一天都有一条测试在守着。

### 2. 模板只管「已经过去的时间」

可以给每个星期几配一张日程表（几点上班、几点吃饭），到点了它自动把空白填上。
它**不依赖后台保活**（安卓后台限制你懂的），你下次打开 App 时才懒结算 —— 反正时间已经过去了，
补起来和实时填是一回事。而且它**只填空白，绝不覆盖你手记过的内容**。

### 3. 图形不能说谎

时间线的每一段**按真实高度画**。想让细段好点就把它画高一点？那「看到的」和「点到的」就脱节了 ——
所以点击判定改成**按分钟反查坐标**，而不是靠把色块加粗去换命中率。

这条踩过坑：曾经为了让 20 分钟的段好点，把它抬到 22dp，结果 22 分钟和 23 分钟两段重叠了 11dp，名字糊成一团。
现在有 13 条纯几何断言专门盯着这件事（`SegGeometryTest`）。

## 界面一览

| 页面 | 干什么 |
|---|---|
| **时间线** | 当天的段按时间排下来，底部一条「现在在干什么」。点「结束」就切下一件事。 |
| **统计** | 周 / 月 / 年视图；单日 24 小时分布；多事项叠加曲线；分类占比。 |

| **桌面小部件** | 当前事项 + 今天色条，可在桌面上直接切换事项。 |

## 30 秒跑起来

**准备**：装 Android Studio（自带 JDK 与 SDK），把手机用数据线连上并开启 USB 调试。

```bash
git clone <本仓库地址>
cd timelog-android
./gradlew :app:installDebug      # Windows 用 gradlew.bat
```

或者直接用 Android Studio 打开，等 Gradle 同步完，点绿色的 ▶。

第一次启动会自动导入 `app/src/main/assets/legacy_timelog.json`（60 天的**合成演示数据**），
所以一进去就有内容看，不是空壳。想清空就从「设置 → 导入旧数据 → 撤销」回退。

> 💡 演示数据是 `tools/gen_demo_data.py` 生成的，跑一遍就能重新造一份 —— 改作息、改事项名都在那个脚本里。

## 项目结构

```
app/src/main/java/com/misaka/timelog/
├── data/           数据层
│   ├── entity/     7 张表的实体（记录、事项、分类、标签、模板…）
│   ├── dao/        SQL 查询
│   ├── repo/       ★ 业务规则的落点（时间线仓库 2600 行，是全项目的心脏）
│   └── import/     旧版数据导入
├── domain/         纯逻辑，不依赖 Android（有大量单元测试就靠这层能跑在 JVM 上）
├── ui/             Compose 界面（screen / sheet / component / stats）
├── cloud/          可选的云同步（自己部署后端才用得上）
└── widget/         桌面小部件（Glance）

app/src/test/       525 条单元测试，30 个测试类
tools/              演示数据生成器等辅助脚本
docs/               ★ 分册文档，从「完全不懂编程」到「能改功能」都有
```

**想从哪开始读**：先看 `docs/04-代码结构导览.md`，它给了一条阅读路径；
最短的一条是 `domain/` → `data/repo/TimelineRepository.kt` → `ui/screen/TimelineScreen.kt`。

## 技术栈

| 用途 | 选了什么 | 为什么 |
|---|---|---|
| 语言 / UI | Kotlin + Jetpack Compose | 单 Activity，页面即函数，改界面不用动 XML |
| 数据库 | Room（SQLite） | 编译期校验 SQL，迁移有测试盯着 |
| 桌面小部件 | Glance **1.1.1** | ⚠️ 1.2.0 依赖 Compose 1.8，与本项目的 BOM 冲突 |
| 图表 | 自绘 Canvas | 只有几张图，引图表库反而更重 |
| 网络 | `HttpURLConnection` | 全项目只有一个接口，不值得为它引 OkHttp |

**权限只有一条：`INTERNET`**（而且只在你打开云同步时才用得上）。没有定位、没有通知、没有存储权限。

## 云同步（可选，需要自建后端）

App 可以把你改过的天增量上传到你自己的后端，让别的 AI 能读到你的记录做分析。
**这不是开箱即用的**：仓库里不含后端代码，地址和 token 都要你自己填（设置页「服务器地址」+「同步 token」）。

默认是**关**的。作者的观点是：往外传数据这件事，不给关就是耍流氓；打开这个开关这个动作本身就该是一次知情同意。

具体接口约定见 `docs/06-数据怎么存的.md` 的「云端」一节。

## 测试

```bash
./gradlew :app:testDebugUnitTest
```

525 条断言，全部跑在 JVM 上（Robolectric），不需要真机、不需要模拟器，约 1 分钟出结果。

它不是「覆盖率好看」那种测试，而是每一批都对应一次真机事故：

- `DensityTest` —— 一天恒 1440 分钟（地基不变式）
- `SegGeometryTest` —— 图形不能说谎（13 条纯坐标断言，不看数据）
- `TemplateNoTemplateLockTest` —— 那个会让模板「一下午不生效」的隐藏坑
- `MinuteHitTest` —— 点到的必须是看到的那一段

想学**怎么给 UI 逻辑写测试**，`docs/08-我们踩过的坑.md` 里有一节专门讲方法论（含三条血的教训）。

## 已知边界

老实说清楚，省得你试完失望：

- **只有安卓**，没有 iOS、没有 Web。
- **单人单设备**。云同步是「备份 + 给 AI 读」，不是多端实时同步，两台手机同时用会打架。
- **没有提醒、没有后台常驻**。这是刻意的：核心数据不依赖任何后台存活。
- **模板不是闹钟**。它只在你打开 App 时补算已经过去的时间，不会实时弹出「该睡觉了」。
- **作者不是专业安卓开发**，很多写法是「够用且测得动」，不是「业界标准架构」。看得不顺眼的地方欢迎提 issue。
